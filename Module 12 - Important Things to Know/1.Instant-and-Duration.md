# `Instant` & `Duration` — Handling Time in Java

> **Say this first:** *"`Instant` is a single moment in time stored as a number of seconds since 1970 UTC. `Duration` is the gap between two instants. I use them instead of `String` because you can do arithmetic on them — `Duration.between(entry, exit)` — and instead of `Date` because `java.time` types are immutable and thread-safe."*

---

## 1. `Instant` — a point on the timeline

No timezone, no formatting. Just a moment.

```java
import java.time.Instant;

Instant now = Instant.now();                           // this moment
Instant t   = Instant.parse("2026-01-01T10:00:00Z");   // from a string — the Z means UTC
```

| Call | Does |
| --- | --- |
| `Instant.now()` | Right now |
| `Instant.parse("2026-01-01T10:00:00Z")` | String → Instant (ISO-8601) |
| `a.isBefore(b)` / `a.isAfter(b)` | Compare two moments |
| `instant.plusSeconds(60)` | A **new** instant 60s later |
| `instant.toString()` | `2026-01-01T10:00:00Z` |

---

## 2. `Duration` — the gap between two instants

```java
import java.time.Duration;

Duration parked = Duration.between(entryTime, exitTime);

parked.toHours();        // 3     whole hours, ROUNDED DOWN
parked.toMinutes();      // 185   total minutes
parked.toMinutesPart();  // 5     leftover minutes after whole hours
parked.isNegative();     // false
```

**⭐ `toHours()` truncates.** 90 minutes gives **1**, not 2. For billing where a started hour is charged in full:

```java
long hours = (long) Math.ceil(parked.toMinutes() / 60.0);   // 90 min → 2
```

> That single line is the **partial-hour edge case** in every parking/rental problem. Getting it wrong is the most common bug in this question.

## 3. ⭐ Why not `String` for time?

```java
String entry = "2026-01-01T10:00:00Z";
String exit  = "2026-01-01T13:00:00Z";
// now what? you cannot subtract strings
```

You'd have to `Instant.parse()` both before doing anything — so you end up with `Instant` anyway, having added a parse step that **throws at runtime** if a string is malformed.

| | `String` | `Instant` |
| --- | --- | --- |
| Arithmetic | ❌ Impossible without parsing | ✅ `Duration.between()` |
| Bad value | Fails at **runtime** | Can't exist — the type guarantees it |
| Comparison | Lexicographic, wrong across formats | ✅ `isBefore()` / `isAfter()` |

> **Rule:** parse at the **edge** (controller / input), keep the typed value everywhere inside.

---

## 4. ⭐ Why not `Date` or `Calendar`?

They're the pre-Java-8 classes, and they're replaced for good reasons:

- **Mutable** — anyone holding your `Date` can change it under you
- **Not thread-safe**, and `SimpleDateFormat` especially so
- Confusing API — months are 0-indexed, so December is `11`

**`java.time` (Java 8+) fixes all of it.** Every type is **immutable**, so `instant.plusSeconds(60)` returns a *new* instant and leaves the original alone — which also makes it safe to share across threads.

---

## 5. ⭐ Never call `now()` inside business logic

```java
// ❌ untestable — you would have to wait 3 real hours to test this
long fee(Ticket t) {
    Duration d = Duration.between(t.getEntryTime(), Instant.now());
}

// ✅ time passed in
long fee(Ticket t, Instant exitTime) { ... }
```

```java
Instant in  = Instant.parse("2026-01-01T10:00:00Z");
Instant out = Instant.parse("2026-01-01T13:00:00Z");
assertEquals(6000, strategy.calculateFeeInPaise(ticket, out));   // runs in 1ms
```

**Who calls `now()` then?** The outermost layer, once:

```java
lot.unpark(ticketId, Instant.now());    // ⭐ clock read at the edge
```

> **The general principle:** push unpredictable things — **clock, random, network** — to the edge and pass the result inward. The core becomes pure input → output, which is testable.

*(Java also has `java.time.Clock` for injecting a fake clock in tests — worth naming if asked, but passing the time in is enough for an interview.)*

## 6. The other `java.time` types (know they exist)

| Type | Use |
| --- | --- |
| **`Instant`** | A machine timestamp. **Default choice for events** |
| `LocalDate` | A date with no time — a birthday |
| `LocalDateTime` | Date + time, **no timezone** — careful, it's ambiguous |
| `ZonedDateTime` | Date + time + zone — for showing a user their local time |
| **`Duration`** | A gap in hours/minutes/seconds |
| `Period` | A gap in years/months/days |

> **Rule of thumb:** store `Instant`, convert to `ZonedDateTime` only when displaying.

---

## 7. Quick Recall

- **`Instant`** = a moment (seconds since 1970 UTC). **`Duration`** = the gap between two
- **`Duration.between(a, b)`** is the whole reason to use them — you can't subtract strings
- **⭐ `toHours()` rounds DOWN** → use `Math.ceil(toMinutes() / 60.0)` to charge a started hour in full
- **Parse at the edge**, keep typed values inside
- **`java.time` is immutable and thread-safe**; `Date`/`Calendar` are mutable and 0-indexed months
- **⭐ Never call `Instant.now()` inside logic** — pass the time in, so it's testable. `now()` belongs in the controller
- Store `Instant`; use `ZonedDateTime` only for display
