# Thread Lifecycle — The 7 States

---

## 1. The states

A thread moves through a fixed set of states from creation to death.

| State | What it means |
| --- | --- |
| **New** | The thread object is created, but `start()` hasn't been called. It isn't running yet |
| **Runnable** | Ready to run and waiting for the CPU to pick it. **Eligible, but not necessarily executing** |
| **Running** | The scheduler picked it — it is actually executing on a core right now |
| **Blocked** | Waiting for a **lock or resource** that another thread is holding |
| **Waiting** | Waiting **indefinitely** for another thread to do something — `wait()`, `join()` |
| **Timed Waiting** | Waiting for a **fixed time** — `sleep(1000)`, `join(500)` |
| **Terminated** | Finished its work, or was stopped. It can never run again |

---

## 2. The transitions

```
    New ──start()──> Runnable ──scheduler picks──> Running ──finishes──> Terminated
                        ▲                            │
                        │                            ├── needs a lock ──> Blocked
                        │                            ├── wait()/join() ──> Waiting
                        └──────── back to Runnable ──┴── sleep(t) ──────> Timed Waiting
```

| From → To | Trigger |
| --- | --- |
| New → Runnable | `start()` is called |
| Runnable → Running | The **thread scheduler** picks it for the CPU |
| Running → Blocked | It needs a resource/lock someone else holds |
| Blocked → Runnable | The resource becomes free |
| Running → Waiting | It calls `wait()`, `join()`, or waits on a lock |
| Waiting → Runnable | Another thread calls `notify()` / `notifyAll()` |
| Timed Waiting → Runnable | The time expires |
| Running → Terminated | `run()` finishes (or the thread is stopped) |

---

## 3. ⭐ Points interviewers push on

**Runnable ≠ Running.** Runnable means "ready and in the queue". Only the **scheduler** decides who actually runs, and you have no control over it. On a single core, many threads sit in Runnable while one is Running.

**Blocked vs Waiting — the common mix-up:**

| | **Blocked** | **Waiting** |
| --- | --- | --- |
| Waiting for | a **lock** held by another thread | another thread to **signal** it |
| Caused by | trying to enter a `synchronized` block | `wait()`, `join()` |
| Gets out when | the lock is released | `notify()` / `notifyAll()` is called |

**Waiting vs Timed Waiting:** `wait()` can hang forever if nobody notifies. `sleep(2000)` always wakes itself up after 2 seconds.

**Terminated is final.** You cannot restart a dead thread — calling `start()` on it throws `IllegalThreadStateException`. Make a new thread object instead.

**Threads that aren't Running use no CPU.** Blocked, Waiting and Timed Waiting threads cost memory, not CPU — which is exactly why you can keep many more I/O-bound threads than you have cores.

---

## 4. Quick Recall

- **7 states:** New → Runnable → Running → (Blocked / Waiting / Timed Waiting) → Terminated
- **`start()`** moves New → Runnable. **The scheduler** moves Runnable → Running
- **Blocked** = waiting for a lock. **Waiting** = waiting for a signal. **Timed Waiting** = waiting for the clock
- **`sleep()`** → Timed Waiting; **`wait()` / `join()`** → Waiting; **`notify()`** wakes a waiting thread
- **Terminated is one-way** — a finished thread can never be restarted
