# Creating Threads in Java — Thread Class & Runnable

---

## 1. The problem: doing things one after another

You place an order, and three notifications must go out:

| Task | Time |
| --- | --- |
| Send SMS | 2 sec |
| Send Email | 3 sec |
| Calculate ETA | 5 sec |

We simulate the delay with `Thread.sleep()` (from `java.lang`).

```java
class OrderService {
    public static void main(String[] args) throws InterruptedException {
        System.out.println("Placing order...");

        sendSMS();                        // 2 sec
        sendEmail();                      // 3 sec
        String eta = calculateETA();      // 5 sec

        System.out.println("Order placed. ETA: " + eta);
    }

    private static void sendSMS() throws InterruptedException {
        Thread.sleep(2000);
        System.out.println("SMS Sent!");
    }

    private static void sendEmail() throws InterruptedException {
        Thread.sleep(3000);
        System.out.println("Email Sent!");
    }

    private static String calculateETA() throws InterruptedException {
        Thread.sleep(5000);
        return "25 minutes";
    }
}
```

**Total time: 2 + 3 + 5 = 10 seconds.**

---

## 2. Why this is bad

Each task must finish before the next one starts. And notice *what* these tasks are doing — **waiting**. Waiting for the SMS gateway, waiting for the mail server.

> During those 2 seconds of SMS waiting, the program is completely **idle**. It could have been sending the email, but it just sits there.

- Time is wasted on nothing
- The system can't handle multiple operations together
- Slow responses, bad user experience, bottlenecks under load

**The fix:** run them concurrently. While SMS waits, email and ETA proceed. Total time becomes the **longest** task, not the sum:

> **10 seconds → 5 seconds.**

---

## 3. Way 1 — Extend the `Thread` class

Make a subclass of `Thread` and override `run()`. Whatever you put in `run()` is what that thread will do.

```java
class SMSThread extends Thread {
    public void run() {                      // the work of this thread
        try {
            Thread.sleep(2000);
            System.out.println("SMS Sent using Thread.");
        } catch (InterruptedException e) { e.printStackTrace(); }
    }
}
// EmailThread (3 sec) and ETACalculationThread (5 sec) are written the same way
```

```java
class Main {
    public static void main(String[] args) throws InterruptedException {
        SMSThread smsThread = new SMSThread();
        EmailThread emailThread = new EmailThread();
        ETACalculationThread etaThread = new ETACalculationThread();

        smsThread.start();      // ⭐ start(), not run()
        emailThread.start();
        etaThread.start();

        smsThread.join();       // main waits here until SMS finishes
        emailThread.join();
        etaThread.join();

        System.out.println("All tasks completed.");   // prints after ~5 sec, not 10
    }
}
```

**The three methods you must know:**

| Method | What it does |
| --- | --- |
| `run()` | Holds the thread's actual work. **You write this** |
| `start()` | Creates a **new thread** and internally calls `run()` on it |
| `join()` | Makes the calling thread (usually `main`) **wait** for this thread to finish |

> **Classic interview trap:** calling `thread.run()` directly does **not** create a new thread — it's just a normal method call on the current thread, and you're back to sequential execution. Always `start()`.

---

## 4. Way 2 — Implement the `Runnable` interface

`Runnable` is a functional interface with a single method, `run()`. Here you define only **the task**; the thread itself is created separately by passing the task to a `Thread` object.

```java
class SMSTask implements Runnable {
    public void run() {
        try {
            Thread.sleep(2000);
            System.out.println("SMS Sent using Runnable.");
        } catch (InterruptedException e) { e.printStackTrace(); }
    }
}
// EmailTask and ETATask are written the same way
```

```java
class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread smsThread   = new Thread(new SMSTask());     // ⭐ task passed into the thread
        Thread emailThread = new Thread(new EmailTask());
        Thread etaThread   = new Thread(new ETATask());

        smsThread.start();
        emailThread.start();
        etaThread.start();

        smsThread.join();
        emailThread.join();
        etaThread.join();

        System.out.println("All tasks completed.");
    }
}
```

**Why `Runnable` is preferred:**
- **Separation of concerns** — `Runnable` is *the task*, `Thread` is *the worker*. The same task object can be handed to many threads
- **Flexibility** — Java allows only one parent class. If you `extend Thread`, that slot is gone forever. Implementing `Runnable` leaves you free to extend any class and implement other interfaces too

> **If asked "Thread class or Runnable?"** — say **Runnable**, because of the single-inheritance limit and because it cleanly separates the task from the thread that runs it.

---

## 5. Shorter ways to write a `Runnable`

You don't always need a whole class for a small task.

**Anonymous class:**

```java
Runnable task = new Runnable() {
    @Override
    public void run() {
        System.out.println("Task done using direct Runnable.");
    }
};
new Thread(task).start();
```

**Lambda (Java 8+)** — `Runnable` has exactly one method, so a lambda can replace it entirely:

```java
Runnable task = () -> System.out.println("Task done using Lambda.");
new Thread(task).start();
```

> Same behaviour, far less boilerplate. Lambdas are the normal way to write short tasks in modern Java.

---

## 6. ⭐ The catch: `run()` returns nothing

Both approaches above share one limitation:

> **`run()` is `void` — it cannot return a value.**

So the ETA task can calculate `"25 minutes"`, but it has no way to hand that string back to `main`. It can only print it.

**This is the Fire-and-Forget pattern:** you start the task and walk away, never waiting for a result or confirmation. The task runs in the background, and the caller doesn't care when or how it ends.

- **Fine for:** sending an SMS, sending an email, writing a log, pushing analytics — nobody needs a return value
- **Not fine for:** calculating an ETA, fetching a price, reading a record — the caller *needs* the answer

> For tasks that must return something, Java gives us **`Callable` and `Future`** — covered in the next file.

---

## 7. Quick Recall

- **Two basic ways:** `extend Thread` (override `run()`) or `implement Runnable` (pass it to `new Thread(task)`)
- **Prefer `Runnable`** — Java has single inheritance, and it separates task from thread
- **`start()` creates the thread; `run()` alone does not** — biggest beginner mistake
- **`join()`** makes `main` wait so it doesn't finish before its threads do
- **Time saved:** sequential = sum of all tasks (10s); concurrent = the longest task (5s)
- **Both are Fire-and-Forget** — `run()` is `void`, so no result can come back
