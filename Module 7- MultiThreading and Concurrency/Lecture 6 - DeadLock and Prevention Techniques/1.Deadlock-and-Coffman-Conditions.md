# Deadlock & the Four Coffman Conditions

---

## 1. What is a deadlock?

**Two or more threads are blocked forever, each waiting for a lock the other is holding.** Nobody can move, nobody will ever give up, and that part of the system freezes permanently.

> **Analogy — the four-way crossing.** Four trains arrive from directions A, B, C and D. Each one blocks the track the next train needs. No train can move until another backs off, and no train backs off. **A perfect circle of waiting.**

---

## 2. The classic example — bank transfers

```java
class TransferTask implements Runnable {
    private final BankAccount from, to;
    private final int amount;

    public void run() {
        synchronized (from) {                    // ⭐ lock 1
            Thread.sleep(100);                   // widens the timing window
            synchronized (to) {                  // ⭐ lock 2 — may block
                from.withdraw(amount);
                to.deposit(amount);
            }
        }
    }
}
```

```java
// T1 transfers A → B
Thread t1 = new Thread(new TransferTask(accountA, accountB, 100), "T1");
// T2 transfers B → A   ⭐ reverse order — this is the bug
Thread t2 = new Thread(new TransferTask(accountB, accountA, 200), "T2");

t1.start(); t2.start();
t1.join();  t2.join();

System.out.println("Both threads finished.");    // ⭐ NEVER printed
```

**Step by step:**

1. T1 locks **Account-A**, then sleeps 100ms
2. During that sleep, T2 locks **Account-B**
3. T1 wakes, wants **Account-B** → held by T2 → **T1 blocks**
4. T2 wants **Account-A** → held by T1 → **T2 blocks**

```
T1:  has A  ──wants──>  B
                        ▲ has B
T2:  has B  ──wants──>  A
```

Both hold what the other needs. Neither releases anything, because a blocked thread **keeps every lock it already owns**.

> **How you spot it:** the program just **hangs**. The final print never appears, no exception is thrown, no CPU is burned. Silence is the symptom.

**The real bug isn't the code — it's the *order*.** Both threads run identical code; they just received their accounts in opposite order.

## 3. ⭐ The four Coffman conditions

A deadlock needs **all four** at the same time. Break any one and it cannot happen.

| # | Condition | Meaning | Train version |
| --- | --- | --- | --- |
| **1** | **Mutual Exclusion** | A resource can be held by only one thread at a time | One train per track segment |
| **2** | **Hold and Wait** | A thread holds one resource while waiting for another | Train holds track A, waits for track B |
| **3** | **No Preemption** | A resource can't be taken away; it must be released voluntarily | No train is pushed off its track |
| **4** | **Circular Wait** | A closed loop of threads, each waiting on the next | A → B → C → D → A |

> **This is the whole topic in one line:** every prevention technique is just a way of **breaking one of these four**.

---

## 4. Quick Recall

- **Deadlock** = two+ threads blocked forever, each holding a lock the other wants
- **Symptom** = the program **hangs silently** — no error, no CPU usage, output just stops
- **Root cause in the bank example** = the **same two locks acquired in opposite orders**
- **Coffman conditions:** Mutual Exclusion, Hold and Wait, No Preemption, Circular Wait — **all four required**
- **Break any one → no deadlock.** That's the basis of every prevention technique
