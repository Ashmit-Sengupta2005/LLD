# Thread Starvation & Fairness

---

## 1. What is thread starvation?

**A thread is starved when it never gets the CPU or the resource it needs**, because other threads keep grabbing it first. The thread isn't broken or blocked by a bug — it's simply always last in line, forever.

> **Analogy:** A queue at a counter where VIPs can cut in. If VIPs keep arriving, the ordinary person at the front **never** gets served — even though nothing is technically wrong with the queue.

**What causes it:**

| Cause | What happens |
| --- | --- |
| **High-priority threads** | They monopolise CPU time, and low-priority threads rarely get scheduled |
| **Infinite blocking** | A thread waits for a lock that busier threads keep re-acquiring before it gets a turn |
| **No fair scheduling** | If the scheduler doesn't enforce fairness, some threads are simply overlooked |

---

## 2. What is fairness?

**Fairness means every thread eventually gets its turn.** A fair scheduler spreads CPU time across all threads instead of letting a few dominate, which is what prevents starvation.

> Starvation is the disease; fairness is the cure.

---

## 3. How to fix it

- **Adjust thread priorities** — don't leave a big gap between high and low priority threads
- **Use fair locks** — `new ReentrantLock(true)` hands the lock to the **longest-waiting** thread instead of whoever grabs it first
- **Time slicing / round-robin** — every thread gets a fixed slice in rotation, so nobody is skipped
- **Fair scheduling algorithms** — choose a scheduler that guarantees turns rather than pure priority
- **Use Executor services** — let a pool and its queue hand out work in order, instead of hand-managed threads competing freely

> **The practical takeaway:** a thread pool with a proper queue solves most starvation problems by itself, because the **queue is FIFO** — tasks are served in the order they arrived.

**Fair locks are not free:** fairness means extra bookkeeping and more context switching, so a fair lock is **slower** than the default unfair one. Use it only when starvation is a real concern.

---

## 4. Quick Recall

- **Starvation** = a thread never gets the CPU or resource it needs, because others always win
- **Causes:** priority imbalance, constant lock contention, unfair scheduling
- **Fairness** = guaranteeing every thread a turn
- **Fixes:** balanced priorities, fair locks (`ReentrantLock(true)`), round-robin / time slicing, FIFO queues in an executor
- **Trade-off:** fair locks prevent starvation but run slower than unfair ones
- **Don't confuse it with deadlock:** in **deadlock** nothing moves at all; in **starvation** the system runs fine — one unlucky thread just never gets served
