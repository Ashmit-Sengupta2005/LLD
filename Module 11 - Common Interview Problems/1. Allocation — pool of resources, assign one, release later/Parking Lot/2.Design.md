# Parking Lot — Design

> **One line:** a pool of slots, a ticket per parked car, and pricing behind an interface so it can change.

---

## Step 1 — Clarify

**Functional:** a vehicle enters, gets a slot that fits its type, gets a ticket. On exit, fee is calculated from the duration, slot is freed, receipt is returned.

**Assumptions I state out loud:**
- 4 vehicle types: bike, car, truck, EV. Each needs a matching slot type.
- Multiple floors.
- Pricing is hourly for bike/car/EV, flat for truck.

**Hero use case:** *a car enters, parks for 3 hours, and exits paying the right fee.*

---

## Step 2 — Entities

| Entity | Attributes | Job |
| --- | --- | --- |
| `Vehicle` | `licensePlate`, `type` | the actor |
| `ParkingSlot` | `id`, `floorNumber`, `slotType`, `occupied` | the pool unit |
| `Floor` | `floorNumber`, `List<ParkingSlot>` | groups slots |
| `ParkingLot` | `List<Floor>`, `Map<String,Ticket>` | the container + entry point |
| `Ticket` | `id`, `vehicle`, `slot`, `entryTime`, `active` | proof you parked |
| `Receipt` | `ticketId`, `parkedFor`, `fee` | what you get on exit |

Plus the two interfaces: `PricingStrategy`, `SlotAllocationStrategy`.

> `VehicleType` is an **enum**, not a String. `"PREPAID"` vs `"PREPIAD"` compiles fine; an enum does not.

---

## Step 3 — Flows

**Entry**
```
Vehicle arrives
  -> allocationStrategy.findSlot(floors, vehicle)
      -> slot.assign(vehicle)
          -> new Ticket(...)  -> store in activeTickets
```

**Exit**
```
Ticket presented
  -> duration = exitTime - entryTime
      -> PricingStrategyFactory.forVehicle(type)
          -> strategy.calculateFee(duration)
              -> slot.release()  -> ticket.deactivate()  -> Receipt
```

## Step 4 — Classes

```java
interface PricingStrategy {
    double calculateFee(Duration parkedFor);
}
class HourlyPricing      implements PricingStrategy { ... }   // rate * hours
class FlatPricing        implements PricingStrategy { ... }   // same always
class MonthlyPassPricing implements PricingStrategy { ... }   // returns 0

interface SlotAllocationStrategy {
    Optional<ParkingSlot> findSlot(List<Floor> floors, Vehicle v);
}
class NearestFirstAllocation  implements SlotAllocationStrategy { ... }
class FarthestFirstAllocation implements SlotAllocationStrategy { ... }

class ParkingLot {                                  // Singleton (Bill Pugh)
    private SlotAllocationStrategy allocationStrategy;   // interface, injected
    Ticket  park(Vehicle v, Instant entryTime);
    Receipt unpark(String ticketId, Instant exitTime);
}
```

**Relationships**
- `ParkingLot` **has many** `Floor`, `Floor` **has many** `ParkingSlot` (composition — a slot has no meaning without a floor)
- `Ticket` **has one** `Vehicle` and **one** `ParkingSlot` (association)
- `ParkingLot` depends on the **interfaces**, never on `HourlyPricing` directly (DIP)

**The fit rule lives in `ParkingSlot`, not in the allocation strategy:**
```java
boolean canFit(Vehicle v) { return !occupied && slotType == v.getType(); }
```
That way "a car may use a truck slot when none are free" is a one-line change in one place.

**Layering, in one sentence:** `Controller → ParkingLot (service) → Repository → Domain`. Say it, do not build it — in 40 minutes, `ParkingLot` *is* the service layer and the `Map` *is* the repository.

## Step 5 — Core methods

```java
Ticket  park(Vehicle v, Instant entryTime);                       // the hero flow
Receipt unpark(String ticketId, Instant exitTime);                // fee + release
Receipt unpark(String ticketId, Instant exitTime, PricingStrategy override);
```

⭐ **Pass the time in. Never call `Instant.now()` inside the logic.** It makes the code testable and it is the answer to the clock-skew edge case.

---

## Step 6 — Patterns, with reasons

| Pattern | Where | **Why** |
| --- | --- | --- |
| **Singleton** | `ParkingLot` | Entry and exit gates must see the same slot state. Bill Pugh holder — lazy and thread-safe with no `synchronized` |
| **Strategy** | `PricingStrategy` | Hourly / flat / monthly pass are interchangeable rules. This is what the follow-up plugs into |
| **Strategy** | `SlotAllocationStrategy` | "Nearest to the entrance" becomes a swap, not an edit |
| **Factory** | `PricingStrategyFactory` | Maps `VehicleType` → strategy, so no `if-else` leaks into `ParkingLot` |
| **Adapter** | `PaymentGatewayAdapter` | Only if payment comes up. Wraps Razorpay / Stripe behind one interface |

**If asked "why not Observer?"** — *"nothing here needs to be notified. If I add 'alert the display board when the lot fills up', Observer is exactly right."*

**If asked "why not Builder?"** — *"no object here has many optional fields."*

Naming a pattern you cannot justify is worse than naming fewer.

---

## Step 7 — Edge cases ⭐

| Case | Handling |
| --- | --- |
| **No free slot of that type** | Throw `SlotUnavailableException`. Do not return `null` |
| **Two gates, one slot** | `synchronized` on allocation here; in production an atomic DB update or a row lock |
| **Ticket reused / fake ticket** | `activeTickets` lookup plus an `active` flag → `InvalidTicketException` |
| **Partial hour** | A started hour is charged in full. State the rule — do not leave it implied |
| **Exit before entry (clock skew)** | Reject it. Time is passed in from one source |
| **Lost ticket** | Admin override: find by licence plate, charge a flat penalty |

---

## Steps 8 & 9 — Structure and extensions

```
domain/        Vehicle, ParkingSlot, Floor, Ticket, Receipt
strategy/      PricingStrategy + impls, SlotAllocationStrategy + impls
factory/       PricingStrategyFactory
service/       ParkingLot
```

**Extensions that cost one class and zero edits:**
- weekend / night pricing → one `PricingStrategy`
- EV charging slots → one enum value
- "park nearest the lift" → one `SlotAllocationStrategy`
- display board showing free counts → add Observer

**Say this at the end:** *"None of these touch `ParkingLot`."* That sentence is the OCP answer, and it is what gets marked.

---

## Quick Recall

- **Pool + container + record + actor + varying rule.** Five slots, every allocation problem
- `VehicleType` is an **enum**; the fit rule lives in `ParkingSlot.canFit()`
- `ParkingLot` must contain **no `if-else` on vehicle type and no fee arithmetic** — if it does, the follow-up will break you
- Patterns: **Singleton** (lot) + **Strategy** (pricing, allocation) + **Factory** (picks the strategy)
- Pass time in; never read the clock inside the logic
- Finish by naming an extension your design absorbs without modification
