# Parking Lot — Design

> **One line:** a pool of slots, a ticket per parked car, and pricing behind an interface so it can change.

---

## Step 1 — Clarify

**Functional:** a vehicle enters, gets a slot that fits its type, gets a ticket. On exit, fee is calculated from the duration, slot is freed, receipt is returned.

**Assumptions I state out loud:**
- 4 vehicle types: bike, car, truck, EV. Each needs a matching slot type.
- Multiple floors.
- Pricing is hourly for bike/car/EV, flat for truck.

**Hero use case:** *a car enters, parks for 3 hours, and exits paying the right fee.*

---

## Step 2 — Entities

Write every field with its **type**, mark the keys, and spell out enum values. Vague attributes are where designs fall apart under follow-up questions.

**1. `Vehicle`** — the actor
```
id            : UUID   [PK]
licensePlate  : String
vehicleType   : Enum   (BIKE, CAR, TRUCK, EV)
```

**2. `ParkingSlot`** — the pool unit
```
id            : UUID   [PK]
floorNumber   : int
slotType      : Enum   (BIKE, CAR, TRUCK, EV)
isOccupied    : boolean
```

**3. `Floor`** — groups slots
```
id            : UUID   [PK]
floorNumber   : int
slots         : List<ParkingSlot>
```

**4. `Ticket`** — proof you parked
```
id            : UUID        [PK]
vehicleId     : UUID        [FK → Vehicle.id]
slotId        : UUID        [FK → ParkingSlot.id]
pricingRuleId : UUID        [FK → PricingRule.id]
entryTime     : Timestamp
isActive      : boolean
```

> **⭐ Why `pricingRuleId` sits on the ticket:** it **locks the rate at entry**. If the lot raises prices while a car is parked, that car is still charged what it was quoted. Without it, the fee depends on when you happen to leave — which is a real-world bug and a strong point to raise unprompted.

**5. `Receipt`** — what you get on exit
```
id            : UUID        [PK]
ticketId      : UUID        [FK → Ticket.id]
exitTime      : Timestamp
parkedFor     : Duration
totalFee      : double
paymentStatus : Enum        (PENDING, SUCCESS, FAILED)
```

**6. `PricingRule`** — the rates, as data instead of hardcoded numbers
```
id            : UUID   [PK]
vehicleType   : Enum   (BIKE, CAR, TRUCK, EV)
ruleType      : Enum   (FLAT, HOURLY)
ratePerHour   : double
flatRate      : double
```

**7. `Payment`** — only if payment comes up
```
id            : UUID        [PK]
ticketId      : UUID        [FK → Ticket.id]
amount        : double
gateway       : Enum        (RAZORPAY, STRIPE)
status        : Enum        (PENDING, SUCCESS, FAILED)
```

**8. `ParkingLot`** — the container and entry point
```
floors         : List<Floor>
activeTickets  : Map<String, Ticket>
```

**Result objects** — what the two operations hand back:
```
EntryResult { success: boolean, ticket:  Ticket,  message: String }
ExitResult  { success: boolean, receipt: Receipt, message: String }
```

Plus the two interfaces: `PricingStrategy`, `SlotAllocationStrategy`.

> **⭐ Every type is an enum, never a String.** `"PREPAID"` vs `"PREPIAD"` compiles fine and fails at runtime; an enum fails at compile time.

> **⭐ `[FK → Vehicle.id]` is the table view; in the class you'd hold the object** — `Vehicle vehicle` rather than `UUID vehicleId`. Write the FK form when the interviewer is asking about schema, the object form when they're asking about classes. Saying that out loud shows you know both layers (Module 10, Lecture 2).

> **Why `PricingRule` is an entity, not constants:** rates change without a deploy, and a new vehicle type is a new **row**, not a code edit.

## Step 3 — Flows

**Entry**
```
Vehicle arrives
  -> allocationStrategy.findSlot(floors, vehicle)
      -> slot.assign(vehicle)
          -> new Ticket(...)  -> store in activeTickets
```

**Exit**
```
Ticket presented  -> validate it is active
  -> duration = exitTime - entryTime
      -> PricingStrategyFactory.forRule(ticket.pricingRuleId)
          -> strategy.calculateFee(ticket, exitTime)
              -> PaymentFactory.forGateway(type).pay(ticket, amount)
                  -> if paid:  slot.release()   (isOccupied = false)
                               ticket.deactivate()
                               -> Receipt -> ExitResult
```

> **⭐ Release only after payment succeeds** — the barrier does not lift on an unpaid ticket. And **both** flips matter: entry sets `isOccupied = true`, exit sets it back to `false`. Forget the second one and the lot fills up permanently — the single most common bug in this problem.

## Step 4 — Classes

```java
interface PricingStrategy {
    double calculateFee(Duration parkedFor);
}
class HourlyPricing      implements PricingStrategy { ... }   // rate * hours
class FlatPricing        implements PricingStrategy { ... }   // same always
class MonthlyPassPricing implements PricingStrategy { ... }   // returns 0

interface SlotAllocationStrategy {
    Optional<ParkingSlot> findSlot(List<Floor> floors, Vehicle v);
}
class NearestFirstAllocation  implements SlotAllocationStrategy { ... }
class FarthestFirstAllocation implements SlotAllocationStrategy { ... }

interface PaymentGateway {                          // only the charge, nothing else
    boolean pay(Ticket ticket, double amount);
}
class RazorpayGateway implements PaymentGateway { ... }
class StripeGateway   implements PaymentGateway { ... }
class PayPalGateway   implements PaymentGateway { ... }
```

**The factories** — they exist so no `if/else` on a type string ever reaches `ParkingLot`:

```java
class PricingStrategyFactory {
    static PricingStrategy forRule(PricingRule rule) {
        switch (rule.getRuleType()) {
            case HOURLY: return new HourlyPricing(rule);
            case FLAT:   return new FlatPricing(rule);
            default: throw new IllegalArgumentException("Unknown rule: " + rule.getRuleType());
        }
    }
}

class PaymentFactory {
    static PaymentGateway forGateway(Gateway g) { ... }   // same shape
}
```

> **⭐ Return the object or throw — never `null`, and don't wrap a factory in `Optional`.** An unknown pricing type is a bug, not an expected outcome.

**The lot itself:**

```java
class ParkingLot {                                       // Singleton (Bill Pugh)
    private static class Holder {
        private static final ParkingLot INSTANCE = new ParkingLot();
    }
    private ParkingLot() {}
    public static ParkingLot getInstance() { return Holder.INSTANCE; }

    private SlotAllocationStrategy allocationStrategy;   // interface, injected
    private List<Floor> floors;
    private Map<UUID, Ticket> activeTickets;

    EntryResult park(Vehicle v, Instant entryTime);
    ExitResult  unpark(UUID ticketId, Instant exitTime, Gateway gateway);
}
```

**`unpark()` in outline — note the order:**

```java
ExitResult unpark(UUID ticketId, Instant exitTime, Gateway gateway) {
    Ticket t = activeTickets.get(ticketId);
    if (t == null || !t.isActive()) return new ExitResult(false, null, "Invalid ticket");

    double amount = PricingStrategyFactory.forRule(t.getPricingRule())
                                          .calculateFee(t, exitTime);

    boolean paid = PaymentFactory.forGateway(gateway).pay(t, amount);
    if (!paid) return new ExitResult(false, null, "Payment failed");

    releaseSlot(t);                      // isOccupied = false
    t.deactivate();                      // status = INACTIVE
    activeTickets.remove(ticketId);

    return new ExitResult(true, buildReceipt(t, amount, exitTime), "Thank you");
}
```

> **⭐ Receipt building lives here, not in the gateway.** A receipt looks the same whether you paid by Razorpay or PayPal — putting `generateReceipt()` in the `PaymentGateway` interface would duplicate identical code in every gateway class.

> **⭐ Don't retry local state flips.** Setting `isOccupied = false` cannot "half fail", so wrapping it in a retry loop just spins forever. Retries are for **network** calls — the payment gateway — not for assigning a boolean.

**Relationships**
- `ParkingLot` **has many** `Floor`, `Floor` **has many** `ParkingSlot` (composition — a slot has no meaning without a floor)
- `Ticket` **has one** `Vehicle` and **one** `ParkingSlot` (association)
- `ParkingLot` depends on the **interfaces**, never on `HourlyPricing` directly (DIP)

**The fit rule lives in `ParkingSlot`, not in the allocation strategy:**
```java
boolean canFit(Vehicle v) { return !occupied && slotType == v.getType(); }
```
That way "a car may use a truck slot when none are free" is a one-line change in one place.

**Layering, in one sentence:** `Controller → ParkingLot (service) → Repository → Domain`. Say it, do not build it — in 40 minutes, `ParkingLot` *is* the service layer and the `Map` *is* the repository.

### ⭐ How to decide the controllers

**Name a controller after the *actor*, not the entity.** Ask *"who is calling this?"* — a parking lot has three physically separate callers:

| Actor | Real-world thing | Controller |
| --- | --- | --- |
| Driver arriving | the entry gate machine | `EntryGateController` |
| Driver leaving | the exit gate machine | `ExitGateController` |
| Staff | the admin panel | `AdminController` |

**A method goes where its actor triggers it:**

```java
class EntryGateController {
    EntryResult park(VehicleRequest req) {
        Vehicle v = new Vehicle(req.plate(), req.type());
        return ParkingLot.getInstance().park(v, Instant.now());   // ⭐ clock read at the edge
    }
}

class ExitGateController {
    ExitResult unpark(UUID ticketId, Gateway gateway);            // driver scans the ticket
}

class AdminController {
    void addFloor(int floorNo, int slotCount);
    void updatePricing(VehicleType type, double rate);
    ExitResult lostTicketOverride(String licensePlate, Gateway g);   // not the exit gate!
    OccupancyReport getOccupancy();
}
```

> **Note where the lost-ticket case lands** — `AdminController`, not the exit gate. A driver can't authorise it; staff can. That's the actor rule doing its job.

**Two points worth saying out loud:**

- **Controllers hold no logic.** Take input → call the service → return the result. All three call the **same** `ParkingLot` singleton, which is exactly why it's a Singleton: three controllers, one shared slot state.
- **"Why not one `ParkingLotController` with everything?"** Because then the entry gate could call `updatePricing()`. Separate controllers **are** the permission boundary.

> **The rule generalises:** **one controller per actor.** Splitwise → `UserController`, `GroupController`, `ExpenseController`. BookMyShow → `BookingController` (customer) + `AdminController` (theatre owner adding shows).

## Step 5 — Core methods

```java
Ticket  park(Vehicle v, Instant entryTime);                       // the hero flow
Receipt unpark(String ticketId, Instant exitTime);                // fee + release
Receipt unpark(String ticketId, Instant exitTime, PricingStrategy override);
```

⭐ **Pass the time in. Never call `Instant.now()` inside the logic.** It makes the code testable and it is the answer to the clock-skew edge case.

## Step 6 — Patterns, with reasons

| Pattern | Where | **Why** |
| --- | --- | --- |
| **Singleton** | `ParkingLot` | Entry and exit gates must see the same slot state. Bill Pugh holder — lazy and thread-safe with no `synchronized` |
| **Strategy** | `PricingStrategy` | Hourly / flat / monthly pass are interchangeable rules. This is what the follow-up plugs into |
| **Strategy** | `SlotAllocationStrategy` | "Nearest to the entrance" becomes a swap, not an edit |
| **Factory** | `PricingStrategyFactory`, `PaymentFactory` | Maps a type → the right object, so no `if-else` on type leaks into `ParkingLot` |
| **Strategy / Adapter** | `PaymentGateway` | Razorpay / Stripe / PayPal behind one interface. Call it an **Adapter** if you're wrapping their real SDKs, **Strategy** if you're just picking one — say which and why |

**If asked "why not Observer?"** — *"nothing here needs to be notified. If I add 'alert the display board when the lot fills up', Observer is exactly right."*

**If asked "why not Builder?"** — *"no object here has many optional fields."*

Naming a pattern you cannot justify is worse than naming fewer.

## Step 7 — Edge cases ⭐

| Case | Handling |
| --- | --- |
| **No free slot of that type** | Throw `SlotUnavailableException`. Do not return `null` |
| **Two gates, one slot** | `synchronized` on allocation here; in production an atomic DB update or a row lock |
| **Ticket reused / fake ticket** | `activeTickets` lookup plus an `active` flag → `InvalidTicketException` |
| **Partial hour** | A started hour is charged in full. State the rule — do not leave it implied |
| **Exit before entry (clock skew)** | Reject it. Time is passed in from one source |
| **Lost ticket** | Admin override: find by licence plate, charge a flat penalty |
| **Payment gateway fails / times out** | Keep the ticket **active** and the slot held — never release on an unpaid exit. Retry the call (network, so retry is valid), else return `ExitResult(false, …)` and let them try another gateway |

## Steps 8 & 9 — Structure and extensions

```
domain/        Vehicle, ParkingSlot, Floor, Ticket, Receipt, PricingRule
dto/           EntryResult, ExitResult
strategy/      PricingStrategy + impls, SlotAllocationStrategy + impls
factory/       PricingStrategyFactory, PaymentFactory
adapter/       RazorpayGateway, StripeGateway, PayPalGateway
service/       ParkingLot
repository/    TicketRepository
controller/    EntryGateController, ExitGateController, AdminController
exception/     SlotUnavailableException, InvalidTicketException
```

> **⭐ `strategy/` and `factory/` get their own packages** because they are the **extension points**. When asked *"where would weekend pricing go?"* you point at one folder. Buried inside `service/`, the thing you most want visible is hidden.

> **⭐ DTOs do not go in `domain/`.** `domain` is what you persist; `EntryResult` never is.

**Extensions that cost one class and zero edits:**
- weekend / night pricing → one `PricingStrategy`
- EV charging slots → one enum value
- "park nearest the lift" → one `SlotAllocationStrategy`
- display board showing free counts → add Observer

**Say this at the end:** *"None of these touch `ParkingLot`."* That sentence is the OCP answer, and it is what gets marked.

---

## Quick Recall

- **Pool + container + record + actor + varying rule.** Five slots, every allocation problem
- `VehicleType` is an **enum**; the fit rule lives in `ParkingSlot.canFit()`
- `ParkingLot` must contain **no `if-else` on vehicle type and no fee arithmetic** — if it does, the follow-up will break you
- Patterns: **Singleton** (lot) + **Strategy** (pricing, allocation) + **Factory** (picks the strategy)
- Pass time in; never read the clock inside the logic
- Finish by naming an extension your design absorbs without modification
