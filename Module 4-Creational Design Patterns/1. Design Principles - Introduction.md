# Design Patterns — Interview Notes

## 1. What are Design Patterns?

Design patterns are reusable, proven solutions to commonly occurring software design problems. They are templates for structuring code, not ready-made code implementations.

Purpose: Improve code reusability, maintainability, flexibility, and loose coupling.

## 2. Origin

- Popularized in software engineering by the Gang of Four (GoF).
- Authors: Erich Gamma, Richard Helm, Ralph Johnson, John Vlissides.
- Their 1994 book, Design Patterns: Elements of Reusable Object-Oriented Software, documented 23 design patterns.

## 3. Three Categories of GoF Design Patterns

### A. Creational — How objects are created

Focus on controlling and abstracting object creation.

| Pattern          | Main idea                                                                      |
| ---------------- | ------------------------------------------------------------------------------ |
| Singleton        | Restricts a class to one instance.                                             |
| Factory Method   | Lets subclasses decide which product class to instantiate.                     |
| Abstract Factory | Creates families of related objects without specifying their concrete classes. |
| Builder          | Constructs complex objects step by step.                                       |
| Prototype        | Creates objects by cloning existing instances.                                 |

### B. Structural — How classes and objects are composed

Focus on forming flexible structures and connecting incompatible interfaces.

| Pattern   | Main idea                                               |
| --------- | ------------------------------------------------------- |
| Adapter   | Makes incompatible interfaces work together.            |
| Bridge    | Separates an abstraction from its implementation.       |
| Composite | Represents part-whole hierarchies uniformly.            |
| Decorator | Adds responsibilities to objects dynamically.           |
| Facade    | Provides a simplified interface to a complex subsystem. |
| Flyweight | Shares common state to reduce memory usage.             |
| Proxy     | Controls access to another object.                      |

### C. Behavioral — How objects communicate and distribute responsibilities

Focus on interactions and responsibility allocation.

| Pattern                 | Main idea                                                                     |
| ----------------------- | ----------------------------------------------------------------------------- |
| Observer                | Notifies dependents when an object's state changes.                           |
| Strategy                | Makes algorithms interchangeable.                                             |
| Interpreter             | Defines a representation and interpretation of a language's grammar.          |
| Command                 | Encapsulates a request as an object.                                          |
| Chain of Responsibility | Passes a request along potential handlers.                                    |
| Mediator                | Centralizes communication between objects.                                    |
| State                   | Changes behavior according to an object's state.                              |
| Template Method         | Defines an algorithm's skeleton while allowing subclasses to customize steps. |
| Visitor                 | Adds operations to object structures without changing their element classes.  |
| Iterator                | Traverses a collection without exposing its internal representation.          |
| Memento                 | Captures and restores an object's state.                                      |

Interview tip: Remember the distinction:

- Creational: Object creation.
- Structural: Object composition.
- Behavioral: Object interaction.

The GoF classification contains 5 creational + 7 structural + 11 behavioral = 23 patterns.
