# DIP (Dependency Inversion Principle)

> High-level classes should not depend directly on low-level classes. Both should depend on abstractions, such as interfaces.

---

### Example

Instead of an `OrderService` directly depending on `MySQLDatabase`, it should depend on a `Database` interface. This allows us to switch databases without changing the `OrderService`.

---

### Importance

- Reduces coupling.
- Makes code easier to test and maintain.
- Allows implementations to be changed easily.

---

### Key Concepts

- **High-Level Modules:** The parts of your code that contain the core logic - the brains of your application. They make big decisions and coordinate how different features work together.  
  _Example:_ CEO (makes decisions, plans strategies).

- **Low-Level Modules:** The ones that handle the details - like talking to a database, making API calls, reading files, or providing data. They support the high-level logic by doing the grunt work.  
  _Example:_ Employees (do the actual implementation, logistics, and execution).

- **Abstraction:** The process of hiding implementation details and exposing only the essential behavior. In programming, abstraction is usually achieved using interfaces or abstract classes. It helps high-level modules depend on a general contract instead of directly depending on concrete low-level implementations.  
  _Example:_ A CEO assigns work based on roles or responsibilities, not by depending on one specific employee.
