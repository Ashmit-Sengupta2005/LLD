# SRP (Single Responsibility Principle)

> A class should have **only one responsibility and one reason to change.**

Keep each class focused on a single task instead of handling multiple unrelated tasks.

---

### Importance

- Makes code easier to maintain.
- Reduces coupling.
- Makes changes safer.

---

### Example

A `User` class should manage user data, while a separate `UserRepository` class should handle database operations.

---

### Mistakes People Make

- **a.** Mixing database logic with business logic
- **b.** Mixing UI logic with backend code
