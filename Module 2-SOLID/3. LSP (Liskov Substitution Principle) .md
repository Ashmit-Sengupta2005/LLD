# LSP (Liskov Substitution Principle)

> If `S` is a subtype of `T`, then objects of type `T` may be replaced with objects of type `S` without altering the correctness of the program.  
> This means that any subclass should be substitutable for its parent class without breaking the functionality.

A child class should be usable wherever its parent class is expected **without breaking the program's behavior.**

---

### Example

If `Penguin` extends `Bird`, but the `Bird` class assumes every bird can fly, the design violates LSP because penguins cannot fly.

---

**Key point:** Subclasses should follow the expected behavior of their parent classes.
